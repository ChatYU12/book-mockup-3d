# 书模台 · 教材封面 3D 打样

把两张平面图（封面 185 × 260 mm、书脊 10 × 260 mm）变成可以给出版社和老师看的 3D 书模，
导出透明 PNG 贴 PPT，或导出带背景的成品图。

## 打开

**在线预览：https://chatyu12.github.io/book-mockup-3d/**（GitHub Pages，打开就能用）

或者双击 `index.html`——不需要联网、不需要装任何东西、不需要起本地服务器。
three.js 已经内嵌在这个文件里（约 716 KB），图片全程只在浏览器内存里处理，不会上传到任何地方。

支持 Chrome / Edge / Safari 最新版。

## 用

1. **平面图**：把封面图、书脊图拖进左侧两个框（或点击选择）。PNG / JPG。
   请用已经裁到成品尺寸的图，不要带出血线、裁切线。
2. **视角**：五个预设（正面平视、左前 30°、左前 45° 略俯、平放台面、堆叠两本），点一下即切；
   也可以直接在画面上拖拽自由旋转、滚轮缩放。
3. **背景**：透明 / 浅灰影棚 / 纯白无缝 / 木质桌面 / 浅色渐变，或上传自己的背景图。
4. **导出**：选长边 2000 / 3000 / 4000 px，导出 PNG。透明模式导出的图四角 alpha = 0，可直接拖进 PPT。

书模尺寸固定 **185 × 260 × 10 mm**（16 开教材），厚度不随图片变化。

## 几个刻意的设定

- **书脊在封面右侧**。正面朝镜头时书脊出现在右边，书口（纸页侧面）在左边。
  这是按"封面图右边缘与书脊图左边缘拼合"这条需求定的：两张图在接缝处的图案会严格接着。
  副作用：左前视角的预设里看不到书脊，想看封面 + 书脊同框，请把画面拖到右前方（约 +30° ~ +45°）。
- **封面与书脊用同一张拼接贴图**。在 canvas 上把两张图按像素拼好，再给一整块连续 UV 的几何体贴图，
  所以接缝是像素级连续的，不存在"两张贴图对不齐"的问题。
- **封面与书脊之间做了 1.2 mm 折角**（真实书的折痕）。这会让整幅图案横向微缩 0.3%，肉眼不可见。
- **纸页侧面是程序生成的纹理**，不用上传图：10 mm 厚度上叠 100 条纹，模拟纸页层。
- **透明导出的接触阴影是 alpha 渐变**（ShadowMaterial + 程序生成的软阴影贴图），不是画在背景上的灰块。
- **书脊比例校验**：宽高比偏离 10 : 260 超过 5% 会弹警告，并给两个选项——默认「等比缩放并居中裁切」，
  也可以选「拉伸填满」（会变形，但那是你明确选的，不是静默变形）。

## 验证

### 手工验证（2 分钟）

1. 双击打开 → 拖入一张封面图 → 书模出现。再拖入书脊图 → 书脊贴在右侧。
2. 点五个预设，逐个看角度是否符合名字。
3. 在画面上拖拽、滚轮缩放。
4. 背景切到「木质桌面」，再切回「透明」。
5. 选 4000 px，点导出 → 得到 PNG；透明模式下把图拖进 PPT，看有没有灰底。
6. 上传一张比例不对的书脊图（比如 100 × 1000），确认左侧出现黄色比例警告。

### 自动化验收

`tests/` 目录里有 8 条验收标准的自动化检查（puppeteer 驱动本机 Chrome）：

```bash
cd tests
npm i puppeteer-core          # 或者用 /tmp 下的临时安装
node gen-images.mjs           # 生成测试图（带竖彩条的封面/书脊、比例异常的图、自定义背景）
node verify.mjs               # 逐条跑，输出 tests/report.md 和 tests/shots/*.png
```

`report.md` 里每条都给实测数值。

机器上如果同时有别的 Chrome / 自动化在跑，计时会显著偏悲观（我实测过同一台机器从 3s 到 22s 的差异），
所以计时以空载那次为准。`window.__book3d.perf()` 会返回各阶段耗时（`upload:decode` / `upload:composite` /
`upload:firstframe` / `export`），定位慢在哪一步直接看它。

### 本机实测（MacBook Pro / AMD 独显，headless Chrome）

| 项 | 实测 |
| --- | --- |
| 上传封面 + 书脊 → 书模出现 | 2.99 s（含两次解码、两次拼接贴图、首帧着色器编译） |
| 书模包围盒 | 185.000 × 260.000 × 10.000 mm |
| 预设切换到位 | 170 ms 动画，低帧率下 ≤250 ms |
| 透明导出 2000 / 3000 / 4000 px | 2000×1642 / 3000×2464 / 4000×3285，四角 alpha=0，外框 12 px 内可见像素 0 |
| 导出耗时 | 2000 px ≈ 1 s，3000 px ≈ 3 s，4000 px ≈ 5 s（大头是 PNG 编码） |
| 纯白背景角部 | 254, 254, 253 |

### 换了图之后

`__book3d.loadImage(kind, dataURL)`、`setPreset`、`setBackground`、`renderExport` 都可以从控制台直接调，
方便你以后批量出图或者接到别的脚本里。

## 改代码

源码是分开的，`index.html` 是构建产物：

```
src/index.template.html   页面骨架
src/styles.css            样式
src/app.js                全部 3D / 交互 / 导出逻辑
vendor/three.min.js       three.js r160（UMD）
build.mjs                 把上面四个内联成单文件 index.html
```

改完 `src/` 后跑：

```bash
node build.mjs      # 重新生成 index.html
```

不要直接改 `index.html`，会被覆盖。

## 没做的（需求明确排除）

- 封底（现在封底用纸页纹理；要加只多一面贴图）
- 可变厚度 / 按页数算厚度
- 批量处理、多本排队
- 账号、云端存储、分享链接
- PDF / AI / PSD 输入（只吃位图）
- 印刷级输出（CMYK、出血、300 dpi 校色）
- 手机端适配
- 翻页动画、内页展示

## 已知限制

- 导出时按预览区的画面比例出图（所见即所得），不额外裁成固定构图。
- 高分辨率导出靠临时放大渲染尺寸实现，4000 px 在集显机器上约需 3–5 秒（主线程会卡一下）。
- 若浏览器不给 WebGL 透明通道（个别 Safari 版本），导出后会提示"换 Chrome"。
